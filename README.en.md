# ICPC Statement Builder

Polygon's bundled `.sty` files have poor support for Chinese and cannot compile Chinese problem statements out of the box.

ICPC Statement Builder takes a complete contest package exported from Polygon and automatically assembles it into a full ICPC/CCPC-style **Chinese** PDF statement booklet.

> Known limitations: custom content is not well supported (oversized images may overflow, a very long single line in examples does not wrap, etc.). These need manual fixes in the problem's TeX files.

## Quick start (recommended)

1. Download `icpc-statement-builder.exe` from the [Releases](https://github.com/nopostpone/icpc-statement-builder/releases/latest) page.
2. Prepare two things:
   - **Contest package**: the complete contest package exported from **Polygon** (zip or folder). **Make sure the Chinese statements have been entered in it** (i.e. `statements/chinese/` exists), otherwise it cannot be used;
   - **A logo image** for the cover and page headers.
3. Run the exe — it opens a simple GUI where you:
   1. Pick the contest package and a logo image (both **required**);
   2. Fill in the contest name, organizer and date as needed;
   3. Tick "生成 PDF" and/or "导出 Overleaf 目录", then click "生成". "生成 PDF" requires a local XeLaTeX installation.

Outputs are placed in the same directory as the contest package you selected: `<name>.pdf` and `<name>/overleaf/` — the latter can be uploaded to Overleaf and compiled with XeLaTeX.

## Run from source

```bash
git clone https://github.com/nopostpone/icpc-statement-builder.git
cd icpc-statement-builder
```

Dependencies: Python 3.10+; compiling PDFs locally additionally requires XeLaTeX (not needed when only exporting an Overleaf directory). Prepare the contest package as described in "Quick start".

```bash
# Compile a local PDF (generates main.pdf in the project root)
python build.py build <contest-package-folder-or-zip>

# Export an Overleaf directory (in exports/<name>/overleaf/)
python build.py overleaf <contest-package-folder-or-zip>
```

## File responsibilities

- `app-gui.py`: the GUI entry point; the released exe is packaged from it
- `build.py`: the core engine and CLI entry — parses the contest package, reads the problem order and letters, assembles the LaTeX, invokes XeLaTeX, and exports the Overleaf directory
- `main.tex`: master template, loads packages and styles and drives the statement output
- `contest-info.tex`: contest configuration — name, organizer, date, logo path; the problem count is auto-filled by `build.py`
- `generated-problems.tex`: the assembled statements file generated by `build.py` (do not edit by hand)
- `styles/olymp.sty`: Polygon statement typesetting layer (`problem`, input/output, examples, etc.)
- `styles/contest-style.sty`: project-specific layout layer (cover page, headers and footers)
- `gui.spec` / `pdf.spec` / `overleaf.spec`: PyInstaller packaging configs (GUI / legacy drag-and-drop)
- `.build/`, `exports/`: runtime intermediate directories and the CLI-mode export directory

## Conventions

- Only Chinese statements are read: `<contest-package-folder>/problems/<slug>/statements/chinese/problem.tex`
- `\ContestProblemCount` in `contest-info.tex` is auto-filled by `build.py` — do not maintain it by hand; the page counts on the cover and in footers are resolved via `\pageref{LastPage}` automatically, both locally and on Overleaf
- The cover logo size is controlled by `\ContestLogoWidth`, adjust as needed
- The cover logo is not part of the Polygon package; it always uses the project resource path `pic/logo.png` (not included in the repo — bring your own)
- `main.tex` is the master template and rarely needs manual changes
